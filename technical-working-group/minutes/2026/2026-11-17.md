### Mantid modernisation update

- Several people are working on this from different directions.
- Changing an event workspace to be a structure of arrays makes everything a lot faster.
- For some workflows, if you store pixels in equal batches (breaking up the spectrum structure) you can get faster results with parallelisation.
- There will be meetings organised by Pete in the coming months to discuss how to apply these ideas.
  - Get rid of anything we no longer need.
  - Instrument 2.1 (bellow).
  - Moving from an array of structures to a structure of arrays.
  - Improve live data streams (also support streaming out to other systems).
  - Mantid should be easier to use via LLMs and IDE tools (e.g mantid python stubs).
- Instrument 2.1: Work is being done to make Mantid's storing of instrument geometry more memory efficient (calculating on-the-fly rather than storing the geometry for every pixel). This should dramatically reduce the memory requirements for large instruments.
- There is also an ongoing investigation to move mantid to `nanobind` which has a lot of benefits including free-threaded python.
